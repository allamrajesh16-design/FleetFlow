# FleetFlow 30 Essentials Checklist

This document tracks the systematic verification and hardening of FleetFlow across all 30 foundational essentials.

---

## Batch 1: Items 1 to 10

| # | Essential | How it was checked (evidence) | Before | What was fixed | After |
|---|-----------|-------------------------------|--------|----------------|-------|
| 1 | **Public routing** | Verified `/`, `/login`, `/register`, `/verify-otp`, `/forgot-password`, `/404` without login. Tested logged-in state on `/login` and `/register`. Automated test suite in `src/__tests__/ForgotPasswordFlow.test.js` & manual route inspection. | PARTIAL | `RegisterPage.js` lacked the "Already Signed In" card (unlike `LoginPage.js`), and `AppRoutes.js` wrapped `/register` in `PublicOnlyRoute` causing immediate redirect rather than showing the signed-in card. Added "Already Signed In" card to `RegisterPage.js` with switch account/dashboard links and updated route handling. | PASS |
| 2 | **Private routing** | Audited `ProtectedRoute.js`, `LoginPage.js`, and ran `src/__tests__/ProtectedRoute.test.js` (6 passed). Tested unauthenticated access redirects to `/login` with `state: { from: location }`, and post-login redirection strictly restricts to internal paths (`/admin`, `/manager`, `/driver`, `/customer`, `/profile`, `/notifications`), blocking open external redirects. | PASS | Verified existing implementation strictly validates `from.pathname` against allowed internal routes, disallows protocol-relative or external URL redirects, and safely falls back to role dashboard. | PASS |
| 3 | **Role-based routing** | Audited route guards against backend permissions in `AppRoutes.js`, `ProtectedRoute.js`, and sidebar/mobile nav items. Ran full Django backend matrix test (`core.test_permission_matrix` - 31 endpoints tested across 5 role states) and frontend `ProtectedRoute.test.js`. | PASS | Frontend guards (`allowedRoles={['ADMIN']}` etc.) directly align with backend `IsAdmin`, `IsFleetManager`, `IsDriver`, `IsCustomer`. Nav links match role permissions. Unauthorized role visits route to 403 `UnauthorizedPage`. | PASS |
| 4 | **Authentication** | Ran backend authentication test suite (`backend/manage.py test accounts.tests`) covering email & phone login, JWT token issuance, refresh rotation, logout with refresh token blacklist, OTP registration verification, approval checks (`is_approved`), and throttling. | PASS | All 4 auth tests and registration/login flows passed. Confirmed JWT blacklist prevents re-use of revoked tokens and inactive/pending users receive 403 on login. | PASS |
| 5 | **Authorization & Object-Level Isolation** | Created and ran `core/test_object_level_permissions.py` (4 tests) covering Customer booking/payment isolation, Driver trip/fuel/expense isolation, and fleet-wide manager/admin visibility. Ran `core/test_permission_matrix.py` (31 endpoints). | PARTIAL | Missing dedicated automated object-level tests validating that Customer A cannot view Customer B's bookings/payments and Driver A cannot view Driver B's trips/documents/expenses. Added comprehensive `core/test_object_level_permissions.py` validating 403/404/filtered queryset behaviors. | PASS |
| 6 | **Password security** | Inspected Django `AUTH_PASSWORD_VALIDATORS` in `config/settings.py`, password hashing (`PBKDF2PasswordHasher`), password reset flow in `accounts/test_password_reset_otp.py` (8 tests), and searched codebase for plain passwords. | PARTIAL | Found hard-coded demo credentials in documentation (`README.md`, `docs/DEMO_GUIDE.md`). Replaced with environment-configured password instructions (`FLEETFLOW_ADMIN_PASSWORD`). Tested that passwords are never returned in user serializers, reset tokens are hashed in DB (`PasswordResetSession.token_hash`), and OTP resets enforce 5-attempt limit and 10-minute expiry. | PASS |
| 7 | **Session management** | Inspected `AuthContext.js` and `ProtectedRoute.js`. Verified inactivity timer (30 min warning/timeout), refresh token storage, multi-tab logout via `storage` event listener, and Back button cache protection via `pageshow` & `popstate` checks. | PASS | Inactivity timer triggers automatic logout after 30 minutes of idle time. Multi-tab logout synchronizes immediately across browser tabs via `window.addEventListener('storage', ...)`. Bfcache / Back navigation re-evaluates token validity on `pageshow`. | PASS |
| 8 | **Form validation** | Inspected frontend form validators (`src/components/forms/PasswordStrengthMeter.js`, `RegisterPage.js`, `LoginPage.js`, `ForgotPasswordPage.js`) and matching backend serializers (`RegisterSerializer`, `PasswordResetConfirmSerializer`). Ran Jest tests for form flows. | PARTIAL | `PasswordStrengthMeter.css` had hardcoded hex colors violating design token checks. Fixed all hex values with theme CSS variables (`var(--danger)`, `var(--warning-text)`, etc.). Replaced raw buttons with shared accessible `Button` component in `ForgotPasswordPage.js`. Confirmed inline errors display before API calls and backend validation errors map cleanly to form fields. | PASS |
| 9 | **API integration** | Inspected `src/api/client.js`, Axios interceptors, global loading state counters, error normalization (`getApiErrorMessage`), and request cancellation support via `AbortController`. Ran full frontend unit test suite (66 tests passed). | PASS | Single Axios client handles base URL configuration, Bearer token injection, automatic 401 token refresh queue, normalized error handling, and clean promise rejections without unhandled exceptions. | PASS |
| 10 | **Backend validation** | Audited DRF serializers across all apps (`accounts`, `bookings`, `trips`, `payments`, `expenses`, `fuel`, `documents`). Tested model field validation, serializer clean methods, negative payloads, and DB constraints. | PASS | Tested negative inputs in `test_permission_matrix` and `test_password_reset_otp`. Cross-field validations (e.g. travel dates, vehicle statuses, payment amounts, fuel odometer values) enforce business logic before DB commits. | PASS |
